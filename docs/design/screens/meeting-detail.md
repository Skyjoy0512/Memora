# 会議詳細

ルート: `app/meeting/[id].tsx`
種別: Stack（card）

## Purpose

**1つの会議の内容を読む。** 監査 H-3 の解決として、この画面は「読む」ことに集中させる。

現状の FileDetailScreen（1,419行）は、読む・編集する・書き出す・設定する・質問するが同居していた。編集と設定は Bottom Sheet へ、質問は文脈付き Sheet へ分離する。

## User goal

会議で何が話されたかを把握し、必要ならタスクを拾う。

## Information hierarchy

1. **タイトルと日時**（何の会議か）
2. **状態**（処理中なら進捗、完了なら非表示）
3. **タブ**: 要約 / 文字起こし / タスク
4. タブの内容
5. 下部固定: 再生バー（音声がある場合）

**「メモ」タブを廃止する。** タブ枠を消費するほどの独立性がない。メモは要約タブ内のセクションとして持つ。

## Layout

```
┌─────────────────────────────────┐
│ ← 定例会議              [⋯]     │  ネイティブヘッダー
├─────────────────────────────────┤
│ 11月26日 14:00 · 32分 · 週次定例 │
│                                 │
│ ┌─要約─┬─文字起こし─┬─タスク─┐ │  Tabs
│ └──────┴───────────┴────────┘ │
│                                 │
│ スクロール領域                   │
│   （選択中のタブの内容）          │
│                                 │
│                                 │
├─────────────────────────────────┤
│ ▶ ──────●────────  12:34/32:00 │  再生バー
├─────────────────────────────────┤
│ [質問する]                       │  Ask（浮遊レイヤー）
└─────────────────────────────────┘
```

### AskDock の扱い（監査 H-5 の解決）

**AskDock を `footerAccessory` から分離し、独立した浮遊レイヤーにする。**

現状は再生バーと同じ帯に積まれ、footer が高くなるほどコンテンツ末尾が隠れる構造だった。実際に「AI生成」ボタンが押せない不具合が発生している。

新設計:
- Ask は**折りたたまれた状態で下部に浮遊**する（「質問する」の1行）
- タップすると `BottomSheet` が開き、そこで入力・回答表示を行う
- **常時展開された入力欄を置かない**
- 浮遊レイヤーの高さは固定（1行分）なので、コンテンツ余白の計算が単純になる
- 材質は Liquid Glass（iOS 26）。影は使わない

これにより、常駐 UI とスクロールコンテンツの結合が切れる。

## Components

| 要素 | HeroUI Native | Custom |
|---|---|---|
| ヘッダー | Expo Router ネイティブヘッダー | — |
| その他操作 | `Menu` または `BottomSheet` | — |
| タブ | `Tabs`（`.List/.Trigger/.Label/.Indicator/.Content`） | — |
| メタ情報 | `Text`, `Chip` | — |
| 状態 | `Chip` | `StatusChip` |
| 処理中 | `Card` | `ProcessingIndicator`, `ProgressBar` |
| 再生バー | `Slider`（シーク） | `AudioTimeline` |
| Ask 折りたたみ | `Surface` + `PressableFeedback` | `AskDock` |
| Ask 展開 | `BottomSheet` + `TextArea` + `Button` | — |
| 削除確認 | `Dialog` | — |
| タイトル変更 | `Dialog` + `TextField` | — |
| 書き出し | `BottomSheet` + `ListGroup` | — |

## Interactions

| 操作 | 結果 |
|---|---|
| タブ切替 | 内容を切り替え。スクロール位置はタブごとに保持 |
| 再生 | 音声を再生。文字起こしタブなら現在位置を追従 |
| シーク | `Slider` をドラッグ。離したときに `onSeek` |
| 「質問する」 | Ask の `BottomSheet` を開く |
| ⋯（その他） | `BottomSheet`: 書き出し / タイトル変更 / プロジェクト移動 / 削除 |
| 削除 | **`Dialog` で確認**してから実行 |
| 戻る | 元のタブへ（Stack pop） |

## States

| 状態 | 表示 |
|---|---|
| **読み込み中** | `SkeletonGroup` |
| **処理中** | タブの上に `ProcessingIndicator`。完了した内容は読める |
| **完了** | 通常表示 |
| **文字起こし失敗** | 文字起こしタブに `Alert` + 再試行 |
| **要約失敗** | 要約タブに `Alert` + 再試行。文字起こしは読める |
| **音声なし**（インポート後に削除等） | 再生バーを非表示 |
| **オフライン** | クラウド処理が必要な操作を無効化し理由を表示 |

## Accessibility

- タブに `accessibilityRole="tab"` + `accessibilityState={{ selected }}`
- タブ切替時、コンテンツ領域へフォーカスを移す
- 再生バーの `Slider` に `accessibilityValue`（現在位置 / 全体）
- Ask を開いたとき、`BottomSheet` 内へフォーカスを移す。閉じたら元に戻す
- 削除の `Dialog` は破壊的であることを読み上げで伝える
- ヘッダーの ⋯ に `accessibilityLabel="その他の操作"`
- 全タップ領域 44pt 以上

## Acceptance criteria

1. タブが**要約 / 文字起こし / タスクの3つ**である（メモタブは廃止）
2. **AskDock が `footerAccessory` から分離され、独立した浮遊レイヤーになっている**
3. Ask は折りたたみ状態が既定で、タップで `BottomSheet` が開く
4. **コンテンツ末尾が再生バーや Ask に隠れない**
5. 処理中でも完了した内容が読める
6. 削除には `Dialog` の確認がある
7. 文字起こしが失敗しても要約タブが独立して動作する
8. タブごとにスクロール位置が保持される
9. VoiceOver でタブの選択状態が伝わる
10. 画面の行数が現状（1,419行）から大幅に削減されている（編集・書き出しの分離により）
