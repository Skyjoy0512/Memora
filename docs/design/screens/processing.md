# 処理中

種別: グローバル状態 + 会議詳細内の表示
関連ルート: 全タブ（グローバルバー）、`meeting/[id]`

## Purpose

**録音後に何が起きているかを、いつでも確認できるようにする。**

監査 H-1「処理中の状態が一覧から追跡できない」および H-2「進捗表示に進捗の実体がない」の解決策。

処理は数分かかることがあり、その間ユーザーは他の作業をする。戻ってきたときに状況が分からないと不安になる。

## User goal

「録音は終わった。いま何が行われていて、あとどれくらいで読めるようになるのか」を知りたい。

## 処理の段階

Memora の処理は複数段階からなる。**それぞれを独立した状態として扱う。**

| 段階 | 進捗の性質 | 表示 |
|---|---|---|
| 保存 | 短時間 | 「保存しています」 |
| **モデル準備** | 決定的（ダウンロード） | **進捗バー + サイズ** |
| 文字起こし | 決定的 | 進捗バー + パーセンテージ |
| 話者の判別 | 非決定的 | `Spinner` |
| 要約の生成 | 非決定的 | `Spinner` |
| タスクの抽出 | 非決定的 | `Spinner` |

**「モデル準備」を独立した段階として明示する。** 初回の文字起こしでは音声認識モデルのダウンロードが発生し、数分かかる。これが不可視だったため「フリーズと区別できない」問題が起きた（監査 H-2）。

## Layout: グローバル処理中バー

全タブの下部、タブバーの直上に固定。

```
┌─────────────────────────────────┐
│ ...コンテンツ...                 │
├─────────────────────────────────┤
│ ⟳ 定例会議 · 文字起こし中  62%   │  ← グローバルバー
│ ▓▓▓▓▓▓▓▓▓▓▓▓░░░░░░░             │
├─────────────────────────────────┤
│ [ホーム][ライブラリ](●)[タスク][設定] │
└─────────────────────────────────┘
```

- 複数件処理中の場合は「他2件」と集約表示
- タップで会議詳細へ
- 録音中は録音バーが優先され、処理中バーは表示しない

## Layout: 会議詳細内

```
┌─────────────────────────────────┐
│   定例会議                       │
│   11月26日 14:00 · 32分          │
│                                 │
│   ┌───────────────────────────┐ │
│   │ 文字起こしを作っています   │ │
│   │ ▓▓▓▓▓▓▓▓▓░░░░░░  62%      │ │
│   │ あと2分ほどで終わります    │ │
│   └───────────────────────────┘ │
│                                 │
│   完了した内容から表示されます    │
│                                 │
└─────────────────────────────────┘
```

**部分的に完了した内容は先に見せる。** 文字起こしが終われば要約を待たずに読める。

## Components

| 要素 | HeroUI Native | Custom |
|---|---|---|
| グローバルバー | `Surface` + `PressableFeedback` | **`RecordingStatusBar`**（処理中も兼用） |
| 進捗バー | — | **`ProgressBar`**（HeroUI に `Progress` なし） |
| 段階表示 | `Text`, `Description` | — |
| 非決定的な待機 | `Spinner` | — |
| 状態 | `Chip` | `StatusChip` |
| 失敗 | `Alert`（`.Indicator/.Title/.Description`）+ `Button` | — |
| 詳細カード | `Card` | `ProcessingIndicator` |

## Interactions

| 操作 | 結果 |
|---|---|
| グローバルバーをタップ | 該当会議の詳細へ |
| 複数件のバーをタップ | ホームの処理中セクションへ |
| 再試行 | 失敗した段階から再実行 |
| 「あとで」 | 失敗を保留し、会議詳細を表示 |

**処理中でも会議詳細を開ける。** 待つことを強制しない。

## States

| 状態 | 表示 | 次の行動 |
|---|---|---|
| **保存中** | 「保存しています」+ `Spinner` | — |
| **モデル準備中** | 「音声認識の準備をしています」+ 進捗バー + サイズ | — |
| **文字起こし中** | 進捗バー + パーセンテージ + 残り時間の目安 | — |
| **要約生成中** | 「要約を作っています」+ `Spinner` | — |
| **完了** | `Toast`「読めるようになりました」 | 会議を開く |
| **部分完了** | 完了した内容を表示。未完了部分のみ進行表示 | 読み始められる |
| **失敗（文字起こし）** | `Alert` + 理由 + 再試行 | 再試行 / あとで |
| **失敗（要約）** | 文字起こしは表示。要約部分のみ失敗表示 | 再試行 |
| **オフラインで中断** | 「オンラインになったら続きを行います」 | 自動再開 |
| **上限到達** | 「今月の上限に達しました」+ プラン案内 | プランを見る |

**失敗は必ず次の行動を持つ。** 「失敗しました」だけで終わらせない（監査 M-4）。

## 進捗が取れない場合の扱い

**決定的進捗が取得できない処理を、決定的なバーで見せない。** 動かないバーはフリーズと誤認される。

- 進捗が取れる: `ProgressBar` + パーセンテージ
- 進捗が取れない: `Spinner` + 現在の段階名

段階名を出すことで「止まっていない」ことが伝わる。

## Accessibility

- グローバルバーに `accessibilityLiveRegion="polite"`。段階が変わったときのみ通知する（頻繁な進捗更新は読み上げない）
- 進捗バーに `accessibilityRole="progressbar"` + `accessibilityValue={{ now, min: 0, max: 100 }}`
- 失敗の `Alert` は `accessibilityLiveRegion="assertive"`
- 再試行ボタンは 44pt 以上
- **Reduce Motion 時も進捗バーは動かす。** 進捗は情報であり装飾ではない

## Copy

**技術用語を使わない**（監査 M-1）。

| 段階 | 表示テキスト |
|---|---|
| 保存 | 「保存しています」 |
| モデル準備 | 「音声認識の準備をしています」（初回のみ・{size} をダウンロード中） |
| 文字起こし | 「文字起こしを作っています」 |
| 話者判別 | 「話している人を分けています」 |
| 要約 | 「要約を作っています」 |
| タスク抽出 | 「やることを探しています」 |
| 完了 | 「読めるようになりました」 |
| 残り時間 | 「あと{n}分ほどで終わります」 |
| 文字起こし失敗 | 「文字起こしができませんでした」 |
| 失敗の理由（例） | 「音声が短すぎるようです」「通信が不安定でした」 |
| 再試行 | 「もう一度試す」 |
| あとで | 「あとで」 |
| オフライン中断 | 「オンラインになったら続きを行います」 |
| 上限到達 | 「今月の文字起こしの上限に達しました」 |

避ける言葉: `queued`, `transcribing`, `summarizing`, `processing`, `failed`, `エラー`, `タイムアウト`

## Acceptance criteria

1. 処理中はどのタブにいても**グローバルバーで状況が分かる**
2. **モデル準備中が独立した段階として表示される**（初回の数分間が不可視にならない）
3. 決定的進捗が取れる段階は**進捗バーとパーセンテージ**を表示する
4. 進捗が取れない段階は `Spinner` + 段階名を表示し、**動かない進捗バーを出さない**
5. 部分完了時、完了した内容を先に読める
6. 失敗時に**必ず次の行動（再試行 / あとで）が提示される**
7. 失敗の理由がユーザーの言葉で説明される
8. 技術用語（`transcribing` 等）が画面に出ない
9. VoiceOver で段階変化が通知され、進捗の細かい更新は読み上げられない
10. Reduce Motion 有効時も進捗バーが機能する
