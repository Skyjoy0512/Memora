# Memora ナビゲーション設計

作成日: 2026-07-26
前提: `docs/decisions/ADR-001-navigation-architecture.md`

## 全体構造

```
RootLayout (app/_layout.tsx)
  GestureHandlerRootView
    HeroUINativeProvider
      BottomSheetModalProvider
        RecordingProvider          ← 録音のグローバル状態
          Stack
            (tabs)                  ← Bottom Tabs
            meeting/[id]            ← 会議詳細（card）
            record                  ← 録音（fullScreenModal）
            search                  ← 検索（modal）
            onboarding              ← 初回のみ（fullScreenModal）
            auth                    ← 認証（fullScreenModal）
            subscription            ← プラン（modal）
```

## Bottom Tabs

| # | ルート | 名称 | 責務 | Primary action |
|---|---|---|---|---|
| 1 | `(tabs)/index` | ホーム | 今の状況の把握 | 処理中／最近の会議を開く |
| 2 | `(tabs)/library` | ライブラリ | 会議を探す | 会議を開く |
| — | — | **録音** | 録音の開始・状態表示 | 録音開始／停止 |
| 3 | `(tabs)/tasks` | タスク | やることの消化 | タスク完了 |
| 4 | `(tabs)/settings` | 設定 | 設定変更 | 各設定項目 |

**中央の録音ボタンはタブとして登録しない。** カスタム `tabBar` 内で描画する（ADR-001 参照）。

### 各タブの責務境界

重複を避けるため、以下を厳守する。

- **ホームは一覧を持たない。** 「処理中」「最近3件」「未完了タスク件数」の要約のみ。全件表示はライブラリ／タスクへ委ねる
- **ライブラリのみが会議の全件一覧と検索を持つ**
- **タスクタブは全会議横断。** 特定会議のタスクは会議詳細内に表示する
- **設定は設定のみ。** アカウント・プランは設定内から遷移する

## Stack / Modal / Bottom Sheet の使い分け

| 種類 | 用途 | 例 |
|---|---|---|
| **Tab** | 並列な主要領域。相互に行き来する | ホーム / ライブラリ / タスク / 設定 |
| **Stack (card)** | 階層を下る。戻る動作が自然 | 会議詳細、プロジェクト詳細、タスク詳細 |
| **Full screen modal** | 現在の文脈を中断し、完了か破棄で終わる | 録音、オンボーディング、認証 |
| **Modal (page sheet)** | 補助的で、閉じれば元に戻る | 検索、プラン |
| **Bottom Sheet** | 現在の文脈を保ったまま操作する | その他の操作、書き出し、生成設定、Ask、プロジェクト選択 |
| **Dialog** | 破壊的操作の確認。選択を強制する | 削除確認、録音の破棄確認 |
| **Menu** | 少数の選択肢を素早く選ぶ | 並び替え、フィルタ |
| **Toast** | 完了・失敗の非侵襲的通知 | 保存しました、コピーしました |

### 判断基準

- **破壊的操作は必ず `Dialog`。** `apple-design` の Agency 原則に従い、取り返しのつく操作には確認を出さない（過剰な確認はユーザーを訓練して読まなくさせる）
- **Bottom Sheet はコンテンツが見えたまま操作できる場合に使う。** 会議詳細で「その他の操作」を開いても本文が見えていることに意味がある
- **Full screen modal は集中を要求する場合のみ。** 録音は他の情報を見せない方が良い

## 録音のナビゲーション

録音は Memora の中核であり、専用の設計を持つ。

### 状態と画面

| 状態 | 画面 | 中央ボタン | グローバルバー |
|---|---|---|---|
| 待機 | — | 録音アイコン | なし |
| セットアップ | `record`（full screen） | — | なし |
| 録音中 | `record` または任意のタブ | 停止アイコン + 経過時間 | 表示（赤系 accent） |
| 一時停止 | 同上 | 再開アイコン + 経過時間 | 表示（点滅なし） |
| 処理中 | 任意 | 録音アイコン（待機に戻る） | 表示（処理中） |

### 録音中のタブ移動

**許可する。** 録音しながら過去の会議を参照したい状況は現実的にある。

- グローバル録音バーを全タブの上部に固定表示する
- バーをタップすると `record` 画面へ戻る
- バー上で停止・一時停止が直接行える（画面遷移なしで止められることが重要）

### 誤操作の防止

音声の喪失は Memora において最も重大な失敗である。

- 停止は1タップで可能（記録は保存される）
- **破棄は `Dialog` による確認を必須とする**
- Android の戻る操作では録音を停止しない。画面が閉じるだけ
- アプリがバックグラウンドに入っても録音を継続する

## 処理中アイテムへの再アクセス

監査 H-1 の解決策。

1. グローバル処理中バー（録音バーと同じ位置。録音中でない時に表示）
2. ホームの「処理中」セクション
3. ライブラリの会議カードに状態 `Chip`

いずれからも会議詳細へ遷移でき、詳細で進捗の内訳が見られる。

## タブを跨いだ遷移ルール

| 起点 | 操作 | 遷移先 | 方式 |
|---|---|---|---|
| ホーム | 会議をタップ | 会議詳細 | Stack push（タブは維持） |
| ライブラリ | 会議をタップ | 会議詳細 | Stack push |
| タスク | 出典会議をタップ | 会議詳細 | Stack push |
| タスク | 会議内タスクを開く | 会議詳細の該当位置 | Stack push + アンカー |
| 任意 | 録音バーをタップ | 録音画面 | Modal presentation |
| 任意 | 中央ボタン | 録音セットアップ | Modal presentation |

**会議詳細は Stack で開き、タブ状態を保持する。** 戻ると元のタブに帰る。

## 検索

- ライブラリ上部の `SearchField` から起動
- ホームからも到達可能（ヘッダーの検索アイコン）
- 検索対象を明示する: 会議タイトル / 文字起こし本文 / 要約 / タスク
- `TagGroup` で対象を絞り込む

## Deep Link

| URL | 遷移先 |
|---|---|
| `memora-rn://meeting/{id}` | 会議詳細 |
| `memora-rn://record` | 録音セットアップ |
| `memora-rn://tasks` | タスクタブ |
| `memora-rn://library?project={id}` | ライブラリ（プロジェクト絞り込み） |

開発用の `preview` / `dev-fonts` は本番ビルドから除外する。

## Safe Area の扱い

- タブバーは下端 safe area を含む高さを持つ
- 中央ボタンはタブバーから上方向にはみ出す（Floating）。はみ出し量は 12pt を上限とし、コンテンツと重ならないようスクロール余白で吸収する
- グローバル録音バーはタブバーの直上に配置し、その高さもコンテンツ余白に加算する
- **コンテンツの余白は「タブバー + グローバルバー + 画面固有の固定要素」の合算で確保する。** 単一の固定値を使わない（監査 H-5 の再発防止）

## アクセシビリティ

- 中央録音ボタン: `accessibilityRole="button"`、`accessibilityLabel` は状態に応じて「録音を開始」「録音を停止」
- グローバル録音バー: `accessibilityLiveRegion="polite"` で状態変化を読み上げ
- タブ: `accessibilityRole="tab"`、選択状態を `accessibilityState={{ selected }}` で表現
- 全タップ領域 44pt 以上。中央ボタンは 64pt
- VoiceOver の読み上げ順: ヘッダー → コンテンツ → 固定要素 → タブバー
