# Memora デザインシステム

作成日: 2026-07-26
基盤: HeroUI Native v1.0.3 テーマ（**OKLCH 形式**）+ Uniwind + Tailwind CSS v4

## ブランドの方向性

Memora は会議を記録し、内容を理解可能にするツールである。ユーザーは**長い文字起こしを読み、要約を吟味し、タスクを拾う**。読むことが中心の道具である。

したがってデザインの方向は次のとおり。

- **静かであること。** 彩度を抑え、文字が主役になる。UI が主張しない
- **フラットであること。** 影を使わない。階層は面のトーン差とヘアラインで表す
- **情報密度を保つこと。** 実用アプリであり、1画面に入る情報量と走査性が重要。マーケティングサイト的な巨大余白は採らない
- **状態が言葉で分かること。** 色だけに頼らず、必ずテキストを伴う

`minimalist-ui` の方向性（クリーン、エディトリアル、モノクローム寄り、タイポグラフィのコントラスト、グラデーションと重い影の排除）と一致する。

## 影を使わない方針

**`shadow` は全面的に使用しない。** HeroUI テーマの `surface-shadow` も無効化する。

理由:
1. 依頼者から明示的に「カードのシャドウは不要」と指示された
2. 低彩度・フラットな方向性と整合する
3. 影は暗所（ダークテーマ）で機能しにくく、両テーマで一貫した階層表現にならない

代替手段:

| 階層 | 表現 |
|---|---|
| 背景 | `background` |
| 面（第1層） | `surface` |
| 面（第2層） | `surface-secondary` |
| 面（第3層） | `surface-tertiary` |
| 境界 | 低不透明度のヘアライン（`border`） |
| 浮遊レイヤー | iOS 26 Liquid Glass（`@callstack/liquid-glass`）。材質で浮遊を表す |

**入れ子にする場合は同心円の角丸を守る。** 内側の半径 = 外側の半径 − padding。

## セマンティックカラー

**色を画面ごとに直接指定しない。** 必ずセマンティックトークンを介する。

HeroUI Native のテーマは OKLCH 形式（`oklch(0.9702 0 0)`）を使う。HSL ではない。

### 基本

| トークン | 用途 |
|---|---|
| `background` | 画面の背景 |
| `foreground` | 背景上の本文 |
| `muted` | 補足・メタ情報 |
| `surface` / `surface-foreground` | 第1層の面 |
| `surface-secondary` | 第2層の面 |
| `surface-tertiary` | 第3層の面 |
| `accent` / `accent-foreground` | 主要 CTA、選択状態 |
| `default` / `default-foreground` | 副次的な操作 |
| `field-background` / `field-foreground` / `field-placeholder` | 入力欄 |
| `overlay` / `overlay-foreground` | モーダル・シートの面 |
| `border` | 境界線 |

### Memora 固有の状態色

Memora は処理状態が多く、これを体系化する必要がある。

| 状態トークン | 意味 | 使用箇所 |
|---|---|---|
| `state-recording` | 録音中 | 中央 CTA、グローバルバー、波形 |
| `state-processing` | 処理中（文字起こし・要約） | `Chip`、進捗バー |
| `state-success` | 完了 | `Chip`、`Toast` |
| `state-warning` | 注意（上限接近、オフライン） | `Alert`、`Chip` |
| `state-error` | 失敗 | `Alert`、`Chip` |
| `state-offline` | オフライン | バナー |
| `state-idle` | 待機・未処理 | `Chip` |

**`state-recording` のみ彩度を上げる。** 録音中であることは誤認が許されない状態であり、低彩度の中で唯一目立つ必要がある。それ以外は全体の静けさを保つ。

**すべての状態はテキストを伴う。** 色だけで状態を表さない（アクセシビリティ要件）。

### 話者の色

文字起こしの話者ラベルは、識別可能で かつ 主張しすぎない色が必要。

- 低彩度の4〜6色を巡回して割り当てる
- 色に加えて話者名（または「話者A」）を必ず表示する
- 隣接する話者に類似色を割り当てない

## タイポグラフィ階層

**本文は Regular。** 日本語を細いウェイトで小さく表示すると漢字が潰れる。以前 ExtraLight を本文に使い「薄くて安っぽい」評価を受けた経緯がある。

| 役割 | ウェイト | 用途 |
|---|---|---|
| Display | ExtraLight | 大きな数値・特別な見出しのみ |
| Screen title | ExtraLight | 画面タイトル（大サイズなので細くても潰れない） |
| Section title | Light | セクション見出し |
| Body | **Regular** | 本文・文字起こし |
| Emphasis | **Medium** | 強調・ボタンラベル |
| Caption | Regular | メタ情報 |

### 行間

- **本文系は 1.45〜1.62。** 長文を読むため十分な行間が必要
- **見出し系は 1.22〜1.40。** 大きい文字は行間を詰めるのがタイポグラフィの定石

この差は意図的な使い分けであり、`CLAUDE.md` §9 の行間規定は本文系に適用されるものと解釈する。

### 文字起こし本文の特別扱い

文字起こしは Memora で最も長く読まれるテキストである。

- 行間を本文より広く取る（1.6〜1.7）
- 1行の文字数を制限する（読みやすさの上限）
- 話者が変わる箇所で明確な区切りを設ける
- 現在再生中のセグメントを背景色で示す（色のみに依存せず、位置の自動スクロールも併用）

## スペーシング

黄金比スケールを維持する。

```
3, 5, 8, 13, 21, 34, 55
```

**巨大余白（80pt 超のセクション間隔など）は採用しない。** Memora は情報密度と走査性が重要な実用アプリであり、マーケティングサイトの余白設計を持ち込むと1画面の情報量が激減する。

## 角丸

```
xs: 4, sm: 8, md: 13, lg: 21, pill: 999
```

入れ子の場合は同心円を守る（内側 = 外側 − padding）。

## タップ領域

- **最小 44pt。** 例外を作らない
- 中央録音ボタン: 64pt
- リスト行: 最小 50pt
- 隣接するタップ対象の間隔: 最小 8pt

## アイコン

```
sm: 16, md: 20, lg: 24, xl: 28
```

- 線の細いアイコンを使う（低彩度・静かな方向性と整合）
- **アイコンのみの操作は主要導線に置かない。** 意味が伝わらないため、ラベルを伴うか、`accessibilityLabel` を必須とする

## モーション

`apple-design` の実装値に従う。

| 用途 | damping ratio | response |
|---|---|---|
| 押下フィードバック | 1.0 | 0.3 |
| 出現・並び替え | 1.0 | 0.4 |
| シート・ドロワー | 0.8 | 0.3 |

**既定は damping 1.0（オーバーシュートなし）。** バウンスはジェスチャが勢いを伴った場合のみ。ただフェードインする要素にオーバーシュートを付けるのは誤り。

Reanimated の spring パラメータへの換算: `k = m(2π/r)²`, `c = 2ζ√(km)`（`m = 1`）

### 原則

- **transform と opacity のみアニメートする。** width / height / margin はレイアウト再計算を招く
- **`scale(0)` から始めない。** `scale(0.95)` + opacity。現実のものは無から現れない
- **`ease-in` を使わない。** 表示は `ease-out` 系
- **押下は press-down で即時反応。** release を待たない
- **入りと出は同じ経路**
- **`AccessibilityInfo.isReduceMotionEnabled` を尊重する。** 有効時は移動を止め、120ms のクロスフェードにする

### 録音中の表現

録音中は**唯一、継続的なモーションを許可する**。録音されていることが一目で分かる必要があるため。

- 波形または音量インジケータをリアルタイムに動かす
- ただし Reduce Motion 有効時は静的な表示（テキスト + 色）に切り替える

## Light / Dark テーマ

両テーマで同等の情報階層を保つ。

- ダークで白飛びさせない。面のトーン差を保つ
- **影に頼らない設計のため、ダークでの階層表現が破綻しにくい**（影は暗所で機能しない）
- コントラスト比: 本文 4.5:1 以上、大きい文字 3:1 以上

## Dynamic Type

**現状未対応。新設計では対応必須とする。**

- 固定 px を使わず、システムの文字サイズ設定に追従する
- 文字が大きくなってもレイアウトが破綻しないよう、余白を相対値で設計する
- 特に文字起こし本文は Dynamic Type の恩恵が大きい

## テーマの実装方針

- HeroUI Native のテーマ変数（OKLCH）を基盤とする
- Memora のブランド値は `src/design/tokens.ts` を正本とし、そこから CSS 変数を生成する仕組みを維持する
- **`global.css` を手で書かない。** 生成物として扱う
- 生成のドリフトは `theme:check` で検出する

**注記**: 本設計フェーズでは `global.css` および `tokens.ts` を変更しない。実装フェーズで Codex が行う。
