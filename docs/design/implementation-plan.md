## 推奨実行順序

**フェーズ1: 基盤（001-005）**
トークンとコンポーネントを先に固める。ここが揺れると全画面に波及する。

**フェーズ2: 骨格（006-008）**
ナビゲーションと常駐 UI。画面実装の前提になる。

**フェーズ3: 中核体験（011-013, 009）**
録音 → 処理 → ホームでの確認。Memora の主要動線を先に通す。

**フェーズ4: 読む体験（014-016）**
会議詳細。最も大きく、最も価値がある。

**フェーズ5: 周辺（010, 017-021）**
ライブラリ、タスク、プロジェクト、検索、設定、認証。

**フェーズ6: 品質（022-024）**
Dynamic Type、アクセシビリティ、Visual QA。

## 各フェーズの完了条件

| フェーズ | 完了条件 |
|---|---|
| 1 | `npm run typecheck` / `theme:check` / `qa:ios:build` が通る |
| 2 | 全タブへ遷移でき、録音 CTA が表示される |
| 3 | 録音 → 停止 → 処理 → ホームで確認、が実機で通る |
| 4 | 会議詳細で要約・文字起こし・タスクが読める |
| 5 | 全画面が到達可能で、空状態・失敗状態が定義どおり |
| 6 | Dynamic Type 最大でレイアウトが破綻しない。VoiceOver で全画面が操作できる |

## 実装しないもの

- 開発用画面（`preview` / `dev-fonts`）の本番ビルドへの含有
- HeroUI Web（`@heroui/react`）の使用
- 新規 UI ライブラリの追加
- 設計資料に無い画面・機能の追加
