# ADR-001: ナビゲーションアーキテクチャ

- ステータス: 承認
- 日付: 2026-07-26
- 決定者: プロダクトデザイン責任者
- 関連: `docs/design/information-architecture.md`, `docs/reviews/current-ui-ux-audit.md`

## 背景

現状の Bottom Tab は「ホーム / タスク / Ask / 設定」の4つで構成されている。監査により次の問題が判明した。

- **C-1**: Memora の中核価値である録音がナビゲーション構造に存在せず、FAB と画面内 CTA からしか到達できない
- **C-2**: 4枠しかないタブの1つを AI 質問が占有する一方、会議一覧・検索・プロジェクトが独立した居場所を持たない
- **C-3**: Project / Meeting / File / Task の関係が UI に表現されていない

これらは画面単位の修正では解決せず、情報設計からの再構成を要する。

## 検討した案

| 案 | 構成 | 中心概念 |
|---|---|---|
| 案1 Capture 中心型 | ホーム / ライブラリ / (録音) / タスク / 設定 | 録る |
| 案2 Library 中心型 | 会議 / プロジェクト / タスク / 設定 | 蓄積と再訪 |
| 案3 Home ダッシュボード型 | ホーム / 検索 / タスク / 設定 | 集約 |

評価の詳細は `docs/design/information-architecture.md` を参照。

## 決定

**案1 Capture 中心型を採用する。**

Bottom Tab を4タブ + 中央アクションで構成する。

```
[ホーム] [ライブラリ] (●録音) [タスク] [設定]
```

あわせて次を決定する。

1. **「File」概念を UI から廃止し「Meeting」に統一する。** 音声ファイルは Meeting の属性とする
2. **「Ask」タブを廃止し、会議詳細内の文脈付き機能へ移す**
3. **中央の録音ボタンはタブではなくアクションとして扱う。** Expo Router のタブ定義には含めず、カスタム `tabBar` 内で描画する

## 理由

**録音をナビゲーション構造の一級市民にすることが、Memora のプロダクト価値を最も正しく表現する。** 中央 CTA はアプリを開いた瞬間に用途を伝え、かつ片手操作で最も押しやすい位置にある。会議が始まった瞬間という最も切迫した状況で、追加のタップを要求しない。

ライブラリを独立タブとすることで、案2 の主要な利点（会議一覧の独立、探索性）をタブ枠1つで取り込める。

「File」の廃止は C-3 の根本解決になる。File と Meeting という二重概念が存在したことが関係を不明瞭にしていた。ユーザーが認知しているのは会議であり、音声ファイルはその属性にすぎない。インポートした音声も「録音方法が異なる会議」として扱えば概念は1つで済む。

## 中央録音ボタンの扱い

**タブとして登録しない。** 理由は次のとおり。

- タブとして登録すると「選択状態」の概念が発生するが、録音はモードであって画面ではない
- Expo Router のタブ状態管理と録音の状態機械が二重管理になる
- タブのアクティブ表示と録音中表示が競合する

代わりに `app/(tabs)/_layout.tsx` のカスタム `tabBar` 内で中央にボタンを描画する。現行の `V6FloatingTabBar` が既にこの方式を採っており、構造を踏襲できる。

### 録音中の状態変化

| 状態 | 中央ボタンの表示 | タブバー |
|---|---|---|
| 待機 | 録音アイコン（accent） | 通常 |
| 録音中 | 停止アイコン + 経過時間 | 上部にグローバル録音バー |
| 一時停止 | 再開アイコン + 経過時間（点滅なし） | 同上 |
| 処理中 | 録音アイコン（通常に戻る） | 上部に処理中バー |

録音中はタブ移動を許可する。他の画面を見ながら録音を続けられることは実用上重要である。グローバル録音バーにより、どのタブにいても状態が分かり、1タップで録音画面へ戻れる。

## 帰結

### 良い影響

- 録音への到達が全画面から1タップになる
- 会議の探索性が向上する（ライブラリ独立）
- 概念が単純化される（File 廃止）
- ホームが軽くなり、拡張しても破綻しにくい

### 受け入れるコスト

- 中央 CTA の実装が非標準になる（既存 `V6FloatingTabBar` の構造を踏襲することで軽減）
- プロジェクトが独立タブを持たない（ライブラリ内の絞り込み軸として提供）
- 既存の `ask-ai.tsx` ルートを廃止するため、移行作業が発生する

### Android 戻る操作

- 録音中に戻るを押しても録音は継続する。録音画面が閉じるだけ
- 録音の停止・破棄は明示的な操作のみで行う（誤操作で音声を失わないため）

### Deep Link

- `memora-rn://meeting/{id}` — 会議詳細
- `memora-rn://record` — 録音開始
- 既存の `memora-rn://preview` は開発用のため本番ビルドから除外する

## 未解決事項

- プロジェクト数が多い利用者向けに、ライブラリ内へプロジェクト一覧ビューを設けるかは、実利用データを見てから判断する
- 中央 CTA の録音中表示に経過時間を出すか、アイコンのみにするかは実機で可読性を確認して決定する
