# Memora 情報設計

更新日: 2026-08-02
状態: 採用
関連: `docs/decisions/ADR-001-navigation-architecture.md`

## 設計の前提

Memora の主要な仕事は次の4つである。

1. 録音・インポート・オンライン会議から記録を作る
2. ファイルとプロジェクトを再訪する
3. 文字起こし・要約・メモを読む
4. 記録を横断して AI に質問し、タスクへつなげる

UI 上の名称は、既存のデータ契約とユーザーが扱う対象に合わせて **ファイル** を維持する。`File → Meeting` の全面改名は行わない。会議はファイルの代表的な作成元であり、データモデルの別エンティティとはしない。

## 採用する構造

```text
NativeTabs
  ホーム      ファイル / プロジェクトの一覧と検索
  タスク      記録から生まれた横断タスク
  AI          ファイル / プロジェクト / 全体への質問
  設定        アプリ・処理・データの設定

中央 FAB（タブではない）
  録音開始
  インポート
  オンライン会議

BottomAccessory
  常駐 AI コンポーザー
```

- Expo Router の `NativeTabs` を使い、独自 `tabBar` は作らない。
- 中央 FAB は作成メニューであり、選択状態を持つタブではない。
- ホームはダッシュボードとライブラリを分離せず、ヘッダーの Select で「ファイル / プロジェクト」を切り替える。
- AI は独立タブを維持する。さらに `NativeTabs.BottomAccessory` に軽量な入力導線を置き、どのタブからも質問を開始できるようにする。
- File Detail は既存の `file/[id]` と Summary / Transcript / Memo を維持する。名称やデータモデルの変更は、実データ配線と別の判断にする。

## 主要エンティティ

```text
Project（分類軸）
  └── AudioFile（録音・インポート・オンライン会議の成果物）
        ├── Transcript
        ├── Summary
        ├── Memo / PhotoAttachment
        └── Task
```

UI 表記は次のとおりとする。

| 内部概念 | UI 表記 |
|---|---|
| `AudioFile` / file route | ファイル、または内容に応じたタイトル |
| `Project` | プロジェクト |
| `Transcript` | 文字起こし |
| `Summary` | 要約 |
| `Memo` | メモ |
| Ask AI | AI、または「聞く」 |

## 画面責務

| 画面 | 主目的 | 持たせない責務 |
|---|---|---|
| ホーム | ファイル / プロジェクトを探して開く | タスクの詳細編集、設定 |
| タスク | 未完了タスクを確認・完了する | ファイル一覧 |
| AI | スコープを選んで質問する | 記録の編集 |
| 設定 | 処理方法とアプリ設定を変える | 日常的な作成操作 |
| File Detail | 要約・文字起こし・メモを読む／編集する | グローバル検索 |
| 録音 | 録音状態を理解して停止・保存する | 過去ファイルの管理 |

## 旧案の扱い

2026-07-26 午前版にあった次の案は採用しない。

- ホームとライブラリを別タブにする
- Ask タブを廃止する
- `File` を UI から廃止して `Meeting` へ全面改名する
- 独自 `TabBar` を実装する
- 中央ボタンを録音専用にする

旧案を参照する資料には履歴としての価値があるが、実装判断では本書、ADR-001、`navigation.md`、`implementation-plan.md` を優先する。
