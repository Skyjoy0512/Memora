# 実装時の疑問点

Codex が実装中に仕様不足を見つけた場合、ここに記録する。

## 記録形式

```markdown
## Q-{番号}: {要約}

- 発生タスク: MEM-UI-{番号}
- 該当箇所: {ファイル / 画面}
- 不明な点: {具体的に}
- 実装をブロックするか: はい / いいえ
- 暫定対応: {ブロックしない場合、どう実装したか}
```

**ブロックする場合は作業を止めて報告すること。推測で実装しない。**

---

## 設計側から申し送る既知の未確定事項

以下は設計フェーズで意図的に確定させなかった項目。実装時に判断し、結果をここに記録すること。

### 色の実値

`docs/design/design-tokens.md` はセマンティックな役割と彩度方針（低彩度、`state-recording` のみ彩度を上げる）を定義したが、**OKLCH の具体値は確定していない**。

HeroUI Native のデフォルトテーマを基準に、Memora のブランド（低彩度）へ調整すること。大きく変える場合は報告する。

### Dynamic Type の実装手段

対応を必須としたが、**手段は指定していない**。レイアウトが破綻しないことを優先して選択すること。

### RecordingWaveform の実装手段

Skia と Reanimated のどちらでも良い。**60fps を維持できること**と、**Reduce Motion 時に静的表示へ切り替わること**が要件。

### データ層への影響

「File → Meeting」は UI 層の概念変更として設計した。`src/types/memora.ts` や SwiftData スキーマの変更が必要かは**未確認**。

必要と判明した場合は、**UI 層の作業を止めて報告すること**（データ層は §8 の保護対象に隣接するため）。

### Android の検証

現状 `apps/mobile-expo/android` が存在しない。各タスクに Android 確認項目を設けたが、**実行環境が無い場合はその旨を報告し、iOS のみで進めてよい**。
