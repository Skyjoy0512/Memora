# Memora 現状 UI/UX 監査

作成日: 2026-07-26
対象: `apps/mobile-expo`（Expo SDK 57.0.8 / React Native 0.86.0 / Expo Router 57.0.8）
方法: リポジトリ全体の静的調査、および実機（iPhone 14 Pro Max / iOS 26）での動作確認済み範囲の知見

## 調査した現状

### 技術構成

| 項目 | 現状 |
|---|---|
| ルーティング | Expo Router（`app/` ディレクトリ） |
| UI ライブラリ | `heroui-native@1.0.6` 導入済み |
| スタイリング | Uniwind 1.10.0 + Tailwind CSS v4 |
| アニメーション | Reanimated 4.5.0（`MotionAppear` / `MotionPressable` / `useReduceMotion` を整備済み） |

| 材質 | `@callstack/liquid-glass` 0.8.0（iOS 26 Liquid Glass） |

## 問題一覧

### Critical

#### C-1. 録音導線がタブに存在せず、アプリの主目的が構造に表れていない

- **該当画面**: 全体（タブ構成）
- **現状**: Bottom Tab は「ホーム / タスク / Ask / 設定」の4つ。録音は `V6FloatingTabBar` 内の FAB と HomeScreen 内 CTA から `CaptureFlowProvider` を呼ぶ形で、**ナビゲーション構造の一級市民になっていない**
- **ユーザーへの影響**: Memora の中核価値は「会議を録る」ことなのに、タブを見ても録音機能の存在が分からない。初回利用者が録音に到達できない可能性がある
- **根本原因**: 情報設計がデータ構造（ファイル / タスク / 設定）に引きずられ、**ユーザーの目的（録る → 読む → 使う）に沿っていない**
- **改善方向**: 録音を情報設計の中心に据える。中央 CTA をタブバーの構造要素として明示的に設計する
- **HeroUI 候補**: `Button`（semantic accent）、`PressableFeedback`、`Surface`

#### C-2. 「Ask」タブがアプリの目的に対して過大な位置を占めている

- **該当画面**: `app/(tabs)/ask-ai.tsx`
- **現状**: 4つしかないタブの1枠を AI 質問が占有。一方で**会議一覧・プロジェクト・検索は独立した居場所を持たない**
- **ユーザーへの影響**: 「過去の会議を探す」という高頻度の目的に対する導線が弱い。Ask は文脈（どの会議について聞くか）が無いと使いにくく、単独タブとしての利用機会が限られる
- **根本原因**: 機能の目立たせたさが、利用頻度・目的の階層より優先されている
- **改善方向**: Ask は会議詳細内の文脈付き機能として再配置し、タブ枠をライブラリ／検索に譲る
- **HeroUI 候補**: `BottomSheet`（文脈付き Ask）、`SearchField`

#### C-3. Project / Meeting / File / Task の関係が UI 上で表現されていない

- **該当画面**: ホーム、タスク、ファイル詳細
- **現状**: `project` は文字列プロパティとして存在し、ホームでプロジェクト別表示に切り替わる導線はあるが、**Projects という概念の独立した居場所がない**。タスクは会議から抽出されるが、タスク画面から出典会議への導線が弱い
- **ユーザーへの影響**: 情報が増えたときに整理・再訪ができない。「あの案件の先週の会議」に辿り着けない
- **根本原因**: データモデル上の関係が UI の階層構造に翻訳されていない
- **改善方向**: Meeting を中心に据え、Project は分類軸、Task は派生物として明示的に関連づける
- **HeroUI 候補**: `ListGroup`、`Chip`（プロジェクトタグ）、`Card` の `Footer` に出典表示

### High

#### H-1. 処理中の状態が一覧から追跡できない

- **該当画面**: ホーム、ファイル詳細
- **現状**: `transcribing` などのステータスは `StatusPill` で表示されるが、**「いま何件処理中か」「あとどれくらいか」を一覧で把握する場所がない**。進捗は文字起こしタブを開かないと分からない
- **ユーザーへの影響**: 録音後に「処理されているのか、失敗したのか」が不明。アプリを離れて戻ったときに状況を再取得できない
- **根本原因**: 状態設計が個別アイテム単位に閉じており、グローバルな進行状況の概念がない
- **改善方向**: ホームに「処理中」セクションを設ける。録音中・処理中はグローバルなステータスバーで常時可視化する
- **HeroUI 候補**: `Card`、`Spinner`、`Chip`。**進捗バーは HeroUI に存在しないため独自実装が必要**

#### H-2. 文字起こしの進捗表示に進捗の実体がない

- **該当画面**: ファイル詳細 / 文字起こしタブ
- **現状**: `TranscriptionProgressCard` が進捗を表示するが、HeroUI に `Progress` が無いため表現手段が限られる。さらに実機では **SpeechAnalyzer のモデルダウンロード中に数分間まったく反応が無い**（ログにも UI にも出ない）
- **ユーザーへの影響**: フリーズと区別できない。初回利用で最も離脱しやすい場面
- **根本原因**: 決定的進捗（determinate progress）を表現するコンポーネントが無く、かつダウンロード進捗が UI 層に伝わっていない
- **改善方向**: 独自の進捗コンポーネントを設計し、「モデル準備中」を独立した状態として扱う
- **HeroUI 候補**: 該当なし（**独自実装**）。補助に `Spinner`、`Description`

#### H-3. ファイル詳細に機能が集中しすぎている（1,419行）

- **該当画面**: `FileDetailScreen`
- **現状**: 概要 / 文字起こし / メモの3タブに加え、生成設定・その他操作・書き出し・削除確認・タイトル変更・モデル選択の各シート、再生バー、AI 質問ドックが同居
- **ユーザーへの影響**: 目的が絞れず、何をする画面なのか分かりにくい。操作の発見性も低い
- **根本原因**: 「1画面 = 1目的」の原則が守られていない
- **改善方向**: 会議詳細を「読む」ことに集中させ、編集・書き出し・設定は明確に分離する
- **HeroUI 候補**: `Tabs`、`BottomSheet`、`Menu`、`Dialog`

#### H-4. 主要 CTA が画面上部に置かれ、片手操作を妨げている

- **該当画面**: ホーム、ファイル詳細
- **現状**: 検索・その他操作・共有などがヘッダー右上に配置。ファイル詳細では戻る・共有・その他が全て上部
- **ユーザーへの影響**: 大画面デバイス（iPhone 14 Pro Max）で親指が届かない
- **根本原因**: デスクトップ的なヘッダー配置の踏襲
- **改善方向**: 高頻度操作を下部に集約。上部は文脈表示（タイトル・戻る）に限定
- **HeroUI 候補**: `BottomSheet`、`Menu`、`Button`

#### H-5. AI 質問ドックがコンテンツを隠す構造になっている

- **該当画面**: ファイル詳細
- **現状**: AskDock が `Screen` の `footerAccessory` に PlayerBar と積まれ、footer が高くなるほどコンテンツ末尾が隠れる。**実際に「AI生成」ボタンが押せない不具合が発生した**（修正済みだが構造的原因は残存）
- **ユーザーへの影響**: 画面下部の操作が到達不能になる
- **根本原因**: 常駐 UI とスクロールコンテンツが同一の余白計算に依存している
- **改善方向**: 常駐入力を独立したレイヤーに分離し、コンテンツ側の余白確保と疎結合にする
- **HeroUI 候補**: `BottomSheet`、`Surface`。Liquid Glass を材質に

### Medium

#### M-1. ステータス表示が技術用語のまま

- **現状**: `queued` / `transcribing` / `summarized` などがそのまま、あるいは直訳で表示される
- **影響**: ユーザーが状態を理解できない
- **改善方向**: 「順番待ち」「文字起こし中」「要約できました」など、行動と結果が分かる言葉へ
- **HeroUI 候補**: `Chip`、`Description`

#### M-2. 空状態の質が低い

- **現状**: `StateViews` に Empty はあるが、**次に何をすべきかの導線が弱い**
- **影響**: 初回利用時に何もできない印象を与える
- **改善方向**: 空状態は「最初の録音を始める」への最短経路として設計する
- **HeroUI 候補**: `Card`（`Title` + `Description` + `Footer` に CTA）

#### M-3. 検索が独立した居場所を持たない

- **現状**: `SearchBar` はホーム内に置かれ、全文検索の対象範囲が不明瞭
- **影響**: 会議が増えたときに探せない
- **改善方向**: 検索を明示的な導線として設計し、対象（会議 / 文字起こし本文 / タスク）を明示する
- **HeroUI 候補**: `SearchField`、`TagGroup`（絞り込み）

#### M-4. オフライン・権限拒否の状態設計が不足

- **現状**: `OfflineBanner` は存在するが、権限拒否・部分失敗・サブスク上限の状態が体系化されていない
- **影響**: 失敗時にユーザーが次の行動を取れない
- **改善方向**: 状態を網羅的に定義し、各状態に「次の行動」を必ず持たせる
- **HeroUI 候補**: `Alert`、`Button`

#### M-5. 「開発者向け」セクションが本番 UI に混在

- **現状**: 設定画面に Bridge 診断情報、フォント比較、HeroUI プレビューが同居
- **影響**: 製品としての完成度を損なう。ただし開発中は有用
- **改善方向**: ビルド構成で分離する設計を明示
- **HeroUI 候補**: `ListGroup`

### Low

#### L-1. タブ名称が機能名になっている

- 「Ask」「設定」は機能名。「ホーム」は内容を表していない
- 改善方向: 内容を表す具体的な名称にする（`apple-design` の「Direct, specific labels beat safe generic ones」）

#### L-2. アイコンのみの操作が複数ある

- ヘッダーの共有・その他がアイコンのみ。意味が伝わりにくい
- 改善方向: 主要操作はラベルを併記、または下部の明示的な操作へ移す

#### L-3. 影の使用が中途半端

- `tokens.shadow` は既にフラット化済みだが、参照が残る箇所がある
- 改善方向: 階層表現を面のトーンとヘアラインに統一

## アクセシビリティ所見

| 観点 | 現状 | 評価 |
|---|---|---|
| タップ領域 44pt | `minHeight: 50` 等で確保されている箇所が多い | おおむね良好 |
| VoiceOver | `accessibilityLabel` / `accessibilityRole` は付与されている | 読み上げ順序は未検証 |
| Dynamic Type | 固定 `fontSize` をトークンで管理。**スケーリング未対応** | 要改善 |
| 色以外の状態表現 | `StatusPill` は色 + テキスト | 良好 |
| コントラスト | 低彩度パレット。本文 Regular 化で改善済み | 要実測 |
| Reduce Motion | `useReduceMotion` を整備済み | 良好 |
| フォーカス移動 | モーダル・シートのフォーカストラップ未確認 | 要改善 |

**最大の課題は Dynamic Type 非対応。** `textStyles` が固定 px のため、システムの文字サイズ設定が反映されない。

---

## 総括

現状の実装は、個々のコンポーネント品質は改善が進んでいる（HeroUI slot 化、影の廃止、本文 Regular 化、モーション整備）が、**情報設計のレベルで根本的な問題を抱えている**。

最大の問題は **C-1（録音がナビゲーション構造に表れていない）** と **C-3（Project / Meeting / Task の関係が UI に無い）** で、これは部分修正では解決しない。情報設計からの再構成が必要である。
